# Domain Docs

> 作成日時: 2026-09-13 02:33

このリポジトリは single-context 構成を採用する。
ドメイン文書を参照するときは、以下の規則に従う。

## 調査前に読む文書

- ルートの `CONTEXT.md`: ドメインの用語と概念を確認する。
- `docs/adr/`: 作業対象に関係する設計判断を読む。

将来ルートに `CONTEXT-MAP.md` が置かれた場合は、
そこから作業対象に関係する各 `CONTEXT.md` をたどる。
その場合は `src/<context>/docs/adr/` の関連する判断も確認する。

文書が存在しない場合は、そのまま作業を進める。
不足を指摘したり、作業開始の条件として作成を提案したりしない。
用語や設計判断が固まった時点で `/domain-modeling` が必要な文書を作成する。

## 文書の配置

- `CONTEXT.md`: リポジトリ全体のドメイン用語・概念
- `docs/adr/`: 番号付きの Architecture Decision Record

## 用語を統一する

Issue のタイトル、提案、仮説、テスト名などでは、
`CONTEXT.md` に定義された用語を使用する。
用語集が避ける同義語へ言い換えない。

必要な概念が未定義の場合は、用語の選択を見直す。
定義が必要であれば `/domain-modeling` で扱う候補として記録する。

## ADR との矛盾を明示する

既存の ADR と矛盾する提案では、該当する ADR と再検討が必要な理由を明示する。
既存の判断を暗黙に上書きしない。
